# C#/WPF Bug Fix Skill for Desktop Lamour

> **Anti-Hallucination:** Verify every class name, interface, namespace, and file path against the codebase before generating code. See [lamour-anti-hallucination](.claude/skills/ct-anti-hallucination/SKILL.md).

## Overview

Structured debugging workflow for C#/WPF bugs in Desktop Lamour. Covers MVVM binding issues, async patterns, DI resolution, XAML resource lookup, and business logic bugs (stock, invoices).

## Debugging Workflow

### Step 1 — Scope (Read 3-4 files max)

Only read the specific files mentioned. Never explore broadly.

Good scope:
- ViewModel exhibiting the issue
- Related UseCase (if business logic bug)
- The XAML view with the binding problem
- ServiceCollectionExtensions (if DI issue)

### Step 2 — Identify Root Cause

**For UI not updating:**
- Is the ViewModel property generated by `[ObservableProperty]`?
- Is the XAML binding using the generated PascalCase property, not the underscore field?
- Is the ViewModel class `partial`? (Required for source generators)
- Is DataContext set correctly on the View?

**For Command not firing:**
- Is the method decorated with `[RelayCommand]`?
- Is the XAML binding `Command="{Binding LoadDataCommand}"` (generated name = method name + "Command")?
- Is the ViewModel class `partial`? (Required)
- Is `CanExecute` returning false unexpectedly?

**For binding errors (check Output window for binding errors):**
- Is the property name spelled correctly (case-sensitive)?
- Is DataContext the correct ViewModel instance?
- Is the path valid (e.g., `{Binding Employee.FullName}` — is `Employee` null)?

**For async deadlock:**
- Is `.Result` or `.Wait()` called on a Task from the UI thread?
- Fix: always `await` all async methods

**For NullReferenceException:**
- Is a DI-injected dependency null? → Check DI registration
- Is an `[ObservableProperty]` string uninitialized? → Initialize to `string.Empty`
- Is `ObservableCollection` not initialized? → Initialize in declaration `= new()`

**For DI resolution failure:**
- Is the service registered in `[Module]ServiceExtensions.cs`?
- Is `AddHttpClient<IService, Service>()` used for HttpClient injection?
- Is the module extension called in App.xaml.cs? e.g., `services.AddEmployeesModule()`

**For XAML resource not found:**
- Is the ResourceDictionary merged in App.xaml?
- Does the `x:Key` match exactly (case-sensitive)?
- Is the resource in AppStyles.xaml or AppTypography.xaml?

**For stock calculation bugs:**
- Is stock deduction done in UseCase (not ViewModel)?
- Is the stock check (`stock >= requested`) before deduction?
- Is the invoice total recalculated after each line item change?

**For invoice total wrong:**
- Is Total calculated in the domain model or UseCase? (Never in ViewModel)
- Is VAT applied correctly: `Total = subtotal * (1 + taxRate)`?
- Is discount applied before or after tax?

### Step 3 — Apply Minimal Fix

Only fix the root cause. Do NOT refactor surrounding code.

### Step 4 — Verify Full Path

Trace end-to-end:

```
User action → XAML Command binding → [RelayCommand] method
  → UseCase.ExecuteAsync() → Repository.GetAsync() → Service.GetFromJsonAsync()
  → Back: Service returns DTO → Repository maps to domain model
  → UseCase returns domain model → ViewModel updates ObservableCollection
  → XAML DataGrid refreshes via binding
```

## Common Bug Patterns & Fixes

### Pattern 1: UI Not Updating — Wrong Property Name in Binding

```xml
<!-- WRONG: binding to field name -->
<TextBlock Text="{Binding _errorMessage}"/>

<!-- CORRECT: binding to generated property name -->
<TextBlock Text="{Binding ErrorMessage}"/>
```

Fix: Use the generated PascalCase property in XAML. Field `_errorMessage` → binding `ErrorMessage`.

### Pattern 2: Command Not Firing — Missing `partial` Keyword

```csharp
// WRONG: source generators don't work without partial
public class EmployeeListViewModel : ObservableObject
{
    [RelayCommand] // Command not generated!
    private async Task LoadAsync() { }
}

// CORRECT:
public partial class EmployeeListViewModel : ObservableObject
{
    [RelayCommand] // LoadAsyncCommand generated
    private async Task LoadAsync() { }
}
```

### Pattern 3: Async Deadlock — Using .Result

```csharp
// WRONG: deadlocks on UI thread
var employees = _useCase.ExecuteAsync().Result;

// CORRECT:
var employees = await _useCase.ExecuteAsync(ct);
```

### Pattern 4: IsLoading Never Resets — Missing finally

```csharp
// WRONG: if exception thrown, IsLoading stays true forever
try
{
    IsLoading = true;
    var result = await _useCase.ExecuteAsync(ct);
}
catch (Exception ex)
{
    ErrorMessage = ex.Message;
}
// MISSING finally!

// CORRECT:
try { IsLoading = true; ... }
catch (Exception ex) { ErrorMessage = ex.Message; }
finally { IsLoading = false; }
```

### Pattern 5: DI Not Registered — NullReferenceException in Constructor

```
System.InvalidOperationException: Unable to resolve service for type 'IGetEmployeesUseCase'
```

Fix: Add to `EmployeesServiceExtensions.cs`:
```csharp
services.AddScoped<IGetEmployeesUseCase, GetEmployeesUseCase>();
```

### Pattern 6: XAML Resource Not Found

```
Exception: Cannot find resource named 'ButtonPrimaryStyle'
```

Fix steps:
1. Grep for `x:Key="ButtonPrimaryStyle"` in `AppStyles.xaml`
2. Verify the ResourceDictionary is merged in App.xaml
3. Check for typos in the key name

### Pattern 7: ObservableCollection Not Updating

```csharp
// WRONG: assigning new instance doesn't update existing XAML binding
Items = new ObservableCollection<Employee>(result);

// CORRECT: modify the existing collection in-place
Items.Clear();
foreach (var item in result)
    Items.Add(item);
```

### Pattern 8: Business Rule — Stock Going Negative

```csharp
// WRONG: no stock validation in UseCase
public async Task ExecuteAsync(ExportInvoiceLine line, CancellationToken ct)
{
    await _repository.CreateLineAsync(line, ct); // Stock could go negative!
}

// CORRECT: validate in UseCase
public async Task ExecuteAsync(ExportInvoiceLine line, CancellationToken ct)
{
    var product = await _productRepository.GetByIdAsync(line.ProductId, ct);
    if (product.Stock < line.Quantity)
        throw new InvalidOperationException($"Insufficient stock for {product.Name}");
    await _repository.CreateLineAsync(line, ct);
}
```

## Debugging Checklist

Before marking a fix complete:

- [ ] Root cause stated in one sentence
- [ ] Fix is minimal (only root cause addressed)
- [ ] `partial class` verified on ViewModel
- [ ] `[ObservableProperty]` field uses PascalCase property name in XAML binding
- [ ] All async methods use `await`, no `.Result` or `.Wait()`
- [ ] `finally { IsLoading = false; }` on all async commands
- [ ] DI registration verified for all new types
- [ ] XAML resource keys verified to exist in AppStyles.xaml
- [ ] Business rule validation in UseCase, not ViewModel

See `docs/project-overview.md` for business rules context.
